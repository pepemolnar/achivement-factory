`CreateAchievementUiState` is a data class holding `name: String`, `icon: String?`, `accent: AccentSwatch`, `target: Int`, `advancedExpanded: Boolean`, `nameError: String?` and `saved: Boolean`. Defaults: empty name, null icon, `AccentSwatch.INDIGO` as the deterministic default, `target = 1`, `advancedExpanded = false`, no error, not saved. `target` defaulting to 1 with the field hidden is the whole point of D-19 — the common once-a-day habit must never have to look at a counter control.

`CreateAchievementViewModel(repository: AchievementRepository)` exposes `val uiState: StateFlow<CreateAchievementUiState>` over a `MutableStateFlow`, plus intent methods `onNameChange(String)`, `onIconChange(String)`, `onAccentChange(AccentSwatch)`, `onTargetChange(String)`, `onToggleAdvanced()` and `onSave()`. Reuse the `companion object { val Factory }` pattern established by `DailyViewModel`.

`onIconChange` reduces the incoming text to its first grapheme cluster using `java.text.BreakIterator.getCharacterInstance()` — not `String.first()`, which splits surrogate pairs and mangles compound emoji — and stores null when the result is blank. There is no curated icon set anywhere: the system emoji keyboard is the picker (D-15).

`onSave` validates that the trimmed name is non-empty, setting `nameError = "Name is required."` and returning without touching the repository when it is not. On success it launches in `viewModelScope`, calls `repository.create(name.trim(), icon, accent, target)` and sets `saved = true`. Guard the save so a second invocation while a save is in flight or after `saved` is true does nothing.

Tier thresholds are not part of this form. TIER-01 is satisfied by the plain-counter path: an achievement created here has all three tier columns null and a working `counterTarget`, and the Bronze/Silver/Gold ladder is Phase 2 work that lands in the advanced section next to the target field.

`CreateAchievementViewModelTest` is a plain JVM test over a fake repository, covering every case in the behavior list.

`CreateAchievementScreen(uiState, onNameChange, onIconChange, onAccentChange, onTargetChange, onToggleAdvanced, onSave, onBack)` is a full screen — a `Scaffold` with a top bar titled "New achievement" in the Heading role and a back arrow from `material.icons.extended`. It is deliberately not a bottom sheet: D-14 requires a screen layout that Phase 3 reuses in edit mode and Phase 2 extends with tier fields, so keep the body a single vertically scrollable `Column` of labelled sections rather than a sheet-height-constrained layout.

Body sections, separated by `lg`(24dp): (1) the name field — an `OutlinedTextField` labelled "Name", `singleLine`, focus indicator in the app accent, showing `uiState.nameError` as supporting text in the Material3 `error` colour when present; (2) the icon field — a compact `OutlinedTextField` labelled "Icon" whose value is the stored glyph, with a hint that the emoji key on the system keyboard picks it, and which delegates all filtering to `onIconChange`; (3) `AccentSwatchPicker`; then a `lg` section break; then (4) `AdvancedSection`.

`AccentSwatchPicker(selected, onSelect)` renders all ten `AccentSwatch` entries as filled circular targets in a wrapping row, each at least 48dp of touch target (the `2xl` token doubles as the accessibility minimum), the selected one marked with a ring or check. Fixed palette only — no free colour input, no HSV wheel, no hex entry (D-16). Every swatch renders its own `AccentSwatch.color()` value so it looks correct in both themes.

`AdvancedSection(expanded, target, onToggle, onTargetChange)` is collapsed by default. Its header is a text button labelled "Advanced" with a chevron from `material.icons.extended` that rotates on expansion, tinted with the app accent when active. Its content — revealed with `AnimatedVisibility` — is `CounterTargetField`, a numeric `OutlinedTextField` labelled "Counter target" showing the current target with helper text explaining that the achievement is done when the count reaches it. Leave a clearly commented insertion point beneath the target field where Phase 2 adds the Bronze/Silver/Gold threshold fields (D-19).

The save button is a filled Material3 `Button` labelled exactly "Save achievement" in the app accent, pinned below the form content.

`AppNavHost` gains `Routes.CREATE = "create"` and a `composable(Routes.CREATE)` destination that obtains `CreateAchievementViewModel` via `viewModel(factory = CreateAchievementViewModel.Factory)`, collects state with `collectAsStateWithLifecycle()`, wires the intent lambdas, passes `onBack = { navController.popBackStack() }`, and uses a `LaunchedEffect(uiState.saved)` to pop the back stack once when `saved` flips true. `DailyScreen`'s FAB now navigates to `Routes.CREATE`. No manual list refresh is needed on return — the Daily tab's `Flow` re-emits on its own, and if it does not, the bug is in the repository, not here.

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-10 | Tampering | SQL injection via the name or icon field | mitigate | Every write goes through Room DAO methods with bound parameters; no string-concatenated SQL and no `@RawQuery` exists in this project. Room's generated statements make this structurally unavailable. |
| T-01-11 | Denial of service | Pathological input — a multi-megabyte pasted name or a pasted document in the icon field | mitigate | `onIconChange` reduces input to a single grapheme cluster via `BreakIterator`. The name field is `singleLine` and trimmed. A long name degrades layout only, on the owner's own device, and is not otherwise constrained. |
| T-01-12 | Tampering | Malformed numeric target crashing the save path | mitigate | `onTargetChange` clamps to a minimum of 1 and falls back to 1 on non-numeric or empty input; covered by a named unit test rather than left to the field's keyboard type. |
| T-01-13 | Repudiation | Double-save creating duplicate achievements on a fast double tap | mitigate | `onSave` is guarded by the in-flight/`saved` flag and the screen pops the back stack once via `LaunchedEffect(uiState.saved)`. |
| T-01-SC | Tampering | Build-time dependency resolution | mitigate | No new dependencies. `material.icons.extended` already resolves through the Compose BOM pinned in plan 01-01. No npm/pip/cargo install exists in this project. |
</threat_model>
