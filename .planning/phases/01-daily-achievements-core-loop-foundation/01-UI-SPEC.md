# Phase 1 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Platform note:** Achievement Factory is a native Android app (Kotlin + Jetpack Compose + Material3), not a web/React project. The template's shadcn/registry sections do not apply — see "Design System" and "Registry Safety" below for how each is resolved instead. All values are expressed in Compose-native units (`dp` for spacing/sizing, `sp` for text) rather than `px`.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none — shadcn/component-registry tooling is a web/React concept; not applicable to a native Android Compose project. The shadcn initialization gate was skipped for this reason. |
| Preset | not applicable |
| Component library | Jetpack Compose **Material3** (`androidx.compose.material3`, Compose BOM 2026.04.01). Material3 **baseline** color scheme is used — no dynamic color / Material You — so the fixed per-achievement accent palette (below) stays legible and predictable across devices, which dynamic color would undermine. |
| Icon library | Two separate icon sources, used for different roles — do not conflate them: (1) **system emoji keyboard** for per-achievement icons (ACH-02), stored as a plain `String`, rendered directly as text glyphs, no curated set to maintain (D-15); (2) `androidx.compose.material.icons.extended` (Material Symbols) for UI chrome only — FAB plus, back arrow, advanced-toggle chevron. The ring→checkmark morph (D-11) is **not** an icon swap — it is a custom `Path`/`Canvas`-driven shape animation (see Motion section), because it must animate continuously out of the closing progress ring. |
| Font | System default — Android's Material3 baseline `Typography` (Roboto Flex). No bundled custom font family; keeps the app installable with zero font-licensing/packaging concerns for a single-device build. |
| Theme | Both light and dark supported via Material3 baseline `lightColorScheme()` / `darkColorScheme()`, following the system setting. No manual in-app theme toggle in this phase (not a requirement). |

## Shape & Elevation

Not part of the generic template but load-bearing for a Compose UI — the executor needs these to build the card, FAB, and celebration treatment consistently.

| Element | Value |
|---------|-------|
| Achievement card corner radius | 16dp |
| Achievement card resting elevation | 1dp (Material3 `Elevation.Level1`) — no elevation change on tap; the whole-card tap target (D-01) should still read as a calm list row, not a pressable button |
| Achievement card min row height | 72dp (40dp icon/ring cluster + 16dp vertical padding × 2) |
| Icon / progress-ring cluster diameter | 40dp icon, ring drawn 3dp stroke at 2dp outset (~46–48dp overall ring diameter) |
| Streak flame badge | 16dp diameter, anchored to the top-end corner of the icon/ring cluster, overlapping by ~4dp |
| FAB | Standard Material3 `FloatingActionButton`, 56dp, M3 default corner radius (16dp), elevation level 3 |
| Snackbar (undo) | Material3 default `Snackbar` shape/elevation, single line + one text action ("Undo") |
| Done-section divider | 1dp `HorizontalDivider`, full-bleed within the list's horizontal padding |

## Spacing Scale

Declared values (must be multiples of 4), expressed in `dp`:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4dp | Icon-to-label gaps, ring stroke inset |
| sm | 8dp | Compact spacing — gap between icon/ring cluster and text block on a card |
| md | 16dp | Default spacing — card internal padding, list item vertical gap, creation-form field spacing |
| lg | 24dp | Section padding — screen horizontal margins, creation-form section breaks (basic fields vs. the advanced-toggle area) |
| xl | 32dp | Layout gaps — space around the Done-section divider |
| 2xl | 48dp | Major section breaks; deliberately reused as the Material accessibility **minimum touch-target size**, so touch-target math and spacing math never conflict |
| 3xl | 64dp | Page-level spacing — FAB clearance above the bottom of the list, detail-screen top padding |

Exceptions:
- FAB diameter is 56dp — a fixed Material3 component spec, not a layout-spacing value, so it is exempt from the 4-scale.
- Achievement card min row height (72dp) and icon/ring cluster (40dp) are component dimensions, not spacing tokens — both are still multiples of 4.
- Progress-ring stroke width (3dp) is a line weight, not a spacing value, and is exempt from the 4-multiple rule.

## Color

Material3 baseline scheme values (light / dark), used for **app chrome** — the neutral 60/30 surfaces plus the one app-level accent used for UI controls (distinct from the per-achievement accent palette below, per D-10):

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | Light `#FFFBFE` / Dark `#1C1B1F` (Material3 `background`/`surface`) | Screen background, list background |
| Secondary (30%) | Light `#F7F2FA` / Dark `#2B2930` (Material3 `surfaceContainer` tone) | Achievement card surface, creation-form field surface, detail-screen surface, snackbar container |
| Accent (10%) | Light `#6750A4` / Dark `#D0BCFF` (Material3 baseline `primary`) | Reserved for: FAB, the "Save" button, the advanced-toggle's active state, the snackbar "Undo" action text, the Name field's focus indicator |
| Destructive | Light `#B3261E` / Dark `#F2B8B5` (Material3 baseline `error`) | Reserved for: the "Name is required" validation message only — no delete/archive actions exist in this phase (ACH-06–08 are Phase 3) |

Accent reserved for: the five app-chrome elements listed above — never the card background, never body text, never used to signal per-achievement identity (that is the job of the palette below).

### Per-Achievement Accent Palette (D-16)

A separate, fixed palette of 10 swatches — one is chosen per achievement at creation (behind the fixed-palette picker, no free color input). Each swatch ships a light-theme and dark-theme hex so it stays legible on both neutral surfaces above (light-theme value ≈ tone 600, dark-theme value ≈ tone 400, following the standard "darker-on-light / lighter-on-dark" contrast pairing):

| Swatch | Light-theme hex | Dark-theme hex |
|--------|------------------|-----------------|
| Red | `#DC2626` | `#F87171` |
| Orange | `#EA580C` | `#FB923C` |
| Amber | `#D97706` | `#FBBF24` |
| Lime | `#65A30D` | `#A3E635` |
| Emerald | `#059669` | `#34D399` |
| Teal | `#0D9488` | `#2DD4BF` |
| Sky | `#0284C7` | `#38BDF8` |
| Indigo | `#4F46E5` | `#818CF8` |
| Violet | `#7C3AED` | `#A78BFA` |
| Pink | `#DB2777` | `#F472B6` |

Reserved for (D-10): the achievement's icon tint or first-letter glyph tint (D-18, when no emoji is set), the progress-ring stroke (D-09), the streak flame badge (D-07), and the completion checkmark morph (D-11). Never the card background or border — the card body stays neutral (Secondary role above) regardless of which swatch is assigned.

## Motion & Celebration Sequence

Not part of the generic template but this is the load-bearing contract for the phase's core value ("the satisfying loop") and was explicitly left to research/planner discretion in CONTEXT.md. All durations use `MaterialTheme`-independent Compose animation APIs (`tween`, `spring`) — no external motion library beyond what's already pinned (Konfetti is reserved for Phase 5 per D-23 and is **not** used here).

### Per-tap feedback (not a completion — every increment before the last one)
- Ring sweep advances one segment: `tween(durationMillis = 150, easing = FastOutSlowInEasing)`.
- No haptic in this phase (D-24) — a hook point (a single no-op `onCompletionEvent` callback parameter) must exist on the celebration component so Phase 5 wires haptics without touching this code.

### Completion sequence (D-21) — sequenced, not simultaneous, ~900ms–1.1s end-to-end
Driven off one `Animatable`/state value representing "this achievement just completed," collected exactly once per event (CELEB-04) — never derived from persisted/recomposed state.

1. **Ring closes** — `spring(dampingRatio = Spring.DampingRatioMediumBouncy, stiffness = Spring.StiffnessMedium)`, starts at t=0.
2. **Icon morphs into checkmark** — custom `Path` morph + scale pulse (1.0 → 1.15 → 1.0) via `spring(dampingRatio = Spring.DampingRatioMediumBouncy, stiffness = Spring.StiffnessMedium)`, starts at t≈250ms (once the ring is visibly near-closed, not before).
3. **Streak flame animates** — scale-pulse on the existing badge, `spring(dampingRatio = Spring.DampingRatioMediumBouncy, stiffness = Spring.StiffnessMedium)`, starts at t≈400ms. **First appearance at streak 1 (D-08, D-22)** gets a distinct "unlock" treatment: `spring(dampingRatio = Spring.DampingRatioLowBouncy, stiffness = Spring.StiffnessLow)` scale from 0 → 1.3 → 1.0, plus a brief color flash from the achievement's own accent swatch — visibly bouncier than every subsequent streak-tick animation.
4. **Card sinks into the Done section** (D-05, D-06) — gated on completion of stages 1–3 via an animation-finished callback/state check, **not** a fixed delay, so it always reads as a consequence of the celebration rather than a timed guess. Reorder animation via `spring(dampingRatio = Spring.DampingRatioLowBouncy, stiffness = Spring.StiffnessLow)` over ~400–500ms, so the movement settles rather than snaps.

### Reduced motion (D-25, honoured from Phase 1)
Read the system setting via `Settings.Global.getFloat(contentResolver, Settings.Global.ANIMATOR_DURATION_SCALE, 1f)`; treat `0f` as reduced-motion-on. When on:
- Every stage above still **occurs** (ring fills, icon becomes a checkmark, flame updates, card moves to Done) — no state is skipped.
- Every duration/spring above collapses to a single ~80–100ms `tween(easing = LinearEasing)` crossfade/snap with no overshoot — the four stages still resolve in the same order but with no perceptible bounce or stagger between them.
- This collapse behavior is the shared code path later celebration tiers (Phase 2) and the full-tab celebration (Phase 5) must reuse, not reimplement.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | FAB: icon-only `+` (Material Symbols "Add"), `contentDescription` = "Add achievement". Creation-screen save button label: **"Save"**. |
| Empty state heading | "No achievements yet" |
| Empty state body | "Tap + to add your first one." |
| Error state | Form validation (Name field blank on Save attempt): **"Name is required."** Data-load failure (Room read error surfaced to the Daily tab): **"Couldn't load your achievements. Restart the app to try again."** |

Undo (D-04) is the only correction action in Phase 1; it is corrective, not destructive, and needs no confirmation step — it is a snackbar action with an implicit time window. |
