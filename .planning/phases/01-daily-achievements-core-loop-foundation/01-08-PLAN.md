In `app/build.gradle.kts`, load it with `java.util.Properties` guarded by a file-existence check, define `signingConfigs { create("release") { … } }` from those values, and have the release build type use it only when the file is present — so a clean checkout without a keystore still configures and builds a debug APK rather than failing at configuration time.

The release build type keeps `isMinifyEnabled = false`, per SKELETON.md: there is no APK size budget on a single-device install, and disabling R8 removes the whole class of "R8 stripped a Room-generated class" failures for zero cost. ## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Signing material ↔ version control | The release keystore and its passwords must never cross into the repository. |
| Installed app ↔ real user data | From the first release install, the phone holds streak history with no backup anywhere. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-31 | Spoofing | Release signing key compromise or loss | mitigate | A local keystore generated by `keytool`, referenced from a gitignored `keystore.properties`, never committed — verified with `git check-ignore` and a `git ls-files` scan rather than by inspection. Play App Signing is not used because there is no store distribution. Loss of the key only costs an uninstall/reinstall on a single owned device. |
| T-01-32 | Tampering (data destruction) | A future schema change wiping streak history | mitigate | `fallbackToDestructiveMigration` grep-gated to zero, the version-1 schema committed, `SchemaExportTest` failing on any version bump without an exported schema, and a `MigrationTestHelper` harness carrying the written rule for the next bump. This is PITFALLS 7, the highest-cost bug available to this app, and after this plan it is enforced by a test rather than by memory. |
| T-01-33 | Information disclosure | Secrets leaking through the built APK | mitigate | The app has no secrets: no API keys, no tokens, no network permission and no accounts. The only sensitive local artefact is the keystore, which is not packaged into the APK. |
| T-01-34 | Tampering | Sideloaded APK modified before install | accept | The owner builds and installs the APK themselves from their own machine over USB. There is no distribution channel between build and device to interpose on. |
| T-01-35 | Elevation of privilege | R8 stripping Room-generated classes in release | mitigate | `isMinifyEnabled = false` for release, so the class of failure does not arise; and the release APK is exercised on the real device in this plan's human check rather than assumed to behave like the debug build. |
| T-01-SC | Tampering | Build-time dependency resolution | mitigate | No new dependencies. `apksigner` and `keytool` come from the already-installed Android build-tools and JDK. No npm/pip/cargo install exists in this project. |
</threat_model>
