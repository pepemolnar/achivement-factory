  <action>
Create `DailyAchievement` in `domain/model/`: `id: Long`, `name: String`, `icon: String?`, `accent: AccentSwatch`, `target: Int`, `count: Int`, `isDone: Boolean`, `currentStreak: Int`, `bestStreak: Int`. It is the only type the UI layer sees; entities never cross into `ui/`.

`AchievementRepository(achievementDao, progressDao, periodEngine, clock)` exposes `observeDaily(): Flow<List<DailyAchievement>>` and `suspend fun create(name: String, icon: String?, accent: AccentSwatch, target: Int): Long`. `observeDaily` computes today's key once per emission with `periodEngine.current(PeriodType.DAILY)` and `combine`s `achievementDao.observeActive("DAILY")` with `progressDao.observeForPeriod(todayKey)`, joining on `achievementId` and mapping to `DailyAchievement`. `isDone` is read from the progress row's stored `done` column, never recomputed from the achievement's current `counterTarget` — that snapshot is what makes a closed period immutable. Achievements with no progress row for today map to `count = 0, isDone = false`. The period key is resolved in Kotlin and bound as a query parameter; SQLite must never be asked to compute what day it is.

`create` writes an `AchievementEntity` with `periodType = "DAILY"`, `createdAtEpochDay = clock.epochDay()`, all three tier thresholds null, `currentStreak = 0`, `bestStreak = 0`, `streakCachedForPeriodKey = null`, and returns the new row id.

`AppContainer` gains a lazily-built `achievementRepository`.

`DailyUiState` is a sealed interface with `Loading`, `Content(outstanding: List<DailyAchievement>, done: List<DailyAchievement>)` and `Error(message: String)`. `Content` exposes `val isEmpty: Boolean` computed from both lists being empty, so the empty-state decision lives in one place. `Content` must never carry any celebration or "should animate" field — that separation is the whole reason CELEB-04 is achievable, and plan 01-07 depends on it holding.

`DailyViewModel(repository: AchievementRepository)` exposes `val uiState: StateFlow<DailyUiState>` built from `repository.observeDaily()`, mapped into `Content` with the done/outstanding split, `catch`-ing upstream failures into `Error("Couldn't load your achievements. Restart the app to try again.")`, and terminated with `stateIn(viewModelScope, SharingStarted.WhileSubscribed(5_000), DailyUiState.Loading)`. Provide a `companion object { val Factory: ViewModelProvider.Factory }` built with `androidx.lifecycle.viewmodel.viewModelFactory` + `initializer`, reaching the container by casting `this[APPLICATION_KEY]` to `AchievementFactoryApp`. This factory pattern is the project convention — every later ViewModel repeats it.

`AchievementRepositoryTest` runs under Robolectric against an in-memory database with a fixed `AppClock`, covering every case in the behavior list that touches persistence. `DailyViewModelTest` is a plain JVM test using Turbine over a fake repository, covering the done/outstanding split, the `Loading` first emission and the `Error` mapping.

## Trust Boundaries

Unchanged from plan 01-01 — single-user, device-local, zero-network, no IPC surface. This plan adds a UI layer and a repository; it opens no new boundary.

| Boundary | Description |
|----------|-------------|
| Room ↔ UI layer | Entity rows are mapped to `DailyAchievement` before crossing into `ui/`. The only data crossing is the owner's own achievement names and counts. |
